Known gaps

Behavior that is undocumented, unverified, or intentionally not implemented.

  1. ssl.activate and ssl.reissue accept approverEmail, httpDcValidation and dnsDcValidation (verified against the sandbox) but do not expose the 0.6 OV/EV organisation option sets, because the API reference does not document them.
  2. users.create, users.login, users.resetPassword, whoisGuard.renew, ssl.create, ssl.renew and ssl.purchaseMoreSans have undocumented response shapes. They return loosely typed results parsed tolerantly: they never throw on an unexpected shape, and fields that cannot be read are simply absent.
  3. dns.setEmailForwarding sends MailBox<n> as spelled in the API reference; the sandbox accepted it (verified by the E2E suite).
  4. CAA (Flag/Tag) records are not supported by dns.setHosts.
  5. ssl.getInfo accepts returnCertificate and sends it, but 1.0 does not parse the certificate body, so the result never contains the certificate.
  6. WhoisGuard allot, unallot and discard are not implemented.
  7. domains.create no longer exposes idnCode, the billing contact and extendedAttributes, which 0.6 did. IDN registrations and some ccTLDs (such as .us, .ca, .eu) need them. Unknown extra keys still pass through the serializer, so you can try a workaround such as nc.domains.create({ ...params, ExtendedAttributes: "..." } as never), unverified against the live API.
  8. Test fixtures marked source: docs or source: go-namecheap-sdk have not all been verified against the live sandbox. scripts/record-fixtures.mjs re-records them from a real sandbox account.
