Errors & safety

Error classes, retry policy and the commands that deserve extra care.

All API, HTTP and response failures are instances of one of three Error subclasses, exported from the package. Programmer or configuration mistakes (an invalid sandbox, dns.setHosts validation, serializer rejections, reserved parameter names) throw a plain TypeError instead.

ClassThrown whenUseful fields
NamecheapErrorThe API answered with Status="ERROR".code (first error number), errors (all)
NamecheapHttpErrorThe request failed (network, timeout, redirect) or the HTTP status is not 2xx.status, statusText, cause
NamecheapParseErrorThe body is not valid XML, is not a Namecheap envelope, or lacks a documented field.message, cause
import { Namecheap, NamecheapError, NamecheapHttpError, NamecheapParseError } from "@fwgapps/namecheap";

const nc = new Namecheap({ apiUser: "user", apiKey: "key", clientIp: "203.0.113.10", sandbox: true });

try {
  await nc.dns.getHosts({ sld: "example", tld: "com" });
} catch (error) {
  if (error instanceof NamecheapError) {
    console.error(error.code, error.message, error.errors);
  } else if (error instanceof NamecheapHttpError) {
    console.error(error.status, error.statusText);
  } else if (error instanceof NamecheapParseError) {
    console.error("Unexpected response shape:", error.message);
  } else {
    throw error;
  }
}

Error messages never contain request data or credentials. Apart from NamecheapError, whose message is Namecheap's own error text, they contain at most short fragments of the response.

Retries and unknown outcomes

Warning. There are no automatic retries, on purpose. Many commands are billed (register, renew, transfer, purchase). Retrying a request whose outcome is unknown could charge you twice. Decide per call whether a retry is safe; read-only commands such as getList or check usually are.

After a billed or account-changing command, a NamecheapParseError (Namecheap answered OK but the response could not be read) or a timeoutMs abort means the outcome is unknown: the action may have been performed. Reconcile with getList or getInfo before retrying.

HTTP 405 means rate limiting. Namecheap answers 405 when you exceed its request limits, so a NamecheapHttpError with status === 405 is a signal to slow down, not a bug in your request.

Safety notes

  • dns.setHosts replaces the whole zone: every record you do not list is deleted. Read the current records with dns.getHosts first and send the complete desired list. An empty hosts list is rejected with a TypeError before anything is sent.
  • dns.setHosts with emailType other than MX: MX records are silently discarded unless the resulting email mode is MX. Because setHosts replaces the whole zone, listing MX hosts under another mode loses your mail routing.
  • Credentials travel in the POST body, never in the URL.
  • The library never logs anything. Do not log the client config or error cause objects from your own code in production.
  • sandbox defaults to production. See Configuration.
